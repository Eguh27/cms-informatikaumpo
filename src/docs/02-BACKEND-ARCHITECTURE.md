# Backend Architecture & Algorithms

Dokumen ini mendeskripsikan struktur, arsitektur, dan algoritma utama yang menggerakkan sistem *backend* dari Portal CMS S1 Teknik Informatika UMPO. Sistem *backend* ini telah dimigrasikan dari pendekatan *statis* (mock data JSON/TS) menjadi sistem manajemen konten terpusat berbasis **Payload CMS**.

## 1. Teknologi Utama (Backend Stack)

Backend saat ini dibangun dengan pendekatan *Headless CMS* terintegrasi:
- **Core CMS Framework**: Payload CMS v3.
- **Environment**: Terintegrasi secara *native* di dalam aplikasi Next.js (App Router), berbagi *server* dan *memory space* yang sama (*monorepo layout*).
- **Database Engine (Development)**: SQLite (`@payloadcms/db-sqlite`). Memanfaatkan file fisik lokal (dinamakan `.d`) tanpa perlu konfigurasi *server* database eksternal untuk proses MVP.
- **ORM / Schema Manager**: Drizzle ORM (internal Payload).
- **Media & Uploads**: Pemrosesan gambar *server-side* menggunakan `sharp`.

## 2. Struktur Data (Collections)

Tidak ada lagi file `mock.ts` berukuran raksasa. Semua entitas telah didefinisikan sebagai **Collections** dalam Payload CMS (`src/collections/`), yang mewakili tabel-tabel terstruktur di dalam database:

- **Users**: Mengelola hierarki autentikasi dan administrator web.
- **Media**: Tabel khusus untuk unggahan file (foto dosen, sampul berita, dokumen). Mendukung *auto-resizing*.
- **News**: Menyimpan artikel dan pengumuman dengan dukungan editor *Rich Text* (Lexical), *slug* dinamis, dan kategori terstruktur.
- **Lecturers**: Mengelola direktori dosen, lengkap dengan NIDN/NIK, keahlian, dan relasi foto profil ke tabel `Media`.
- **CurriculumTracks**: Sistem taksonomi untuk membagi peminatan studi beserta prospek karirnya.
- **Partners**: Mengelola afiliasi dan rekanan industri (misal: PAKO Group, Oracle Academy).

## 3. Algoritma Inti Backend (Core Algorithms)

### A. Algoritma Integrasi Pengambilan Data (*Zero-Network Latency Fetching*)
Berbeda dengan arsitektur klasik (React terpisah dari Express.js via REST API), sistem ini menggunakan **Payload Local API**:
- Ketika Frontend (Server Components) membutuhkan data, alih-alih mengirim *HTTP Request* (menggunakan `fetch('http://.../api/news')`), server langsung mengeksekusi `getPayload()`.
- Algoritma mem-bypass *network layer* dan berinteraksi langsung dengan *database adapter* (Drizzle SQLite).
- **Hasilnya**: Waktu respons data hampir instan tanpa *overhead* koneksi jaringan antar-server.

### B. Algoritma Akses Kontrol (Access Control Logic)
Tiap *Collection* dilindungi oleh kebijakan otorisasi (ACL) di level konfigurasi:
- **Akses Baca (Read)**: Diatur menggunakan fungsi injeksi `read: () => true`, yang mengizinkan publik (Frontend) bebas meminta data tanpa token autentikasi.
- **Akses Tulis (Create/Update/Delete)**: Algoritma bawaan Payload secara implisit (default) memblokir modifikasi tanpa token sesi admin yang sah. Hanya *User* terotentikasi yang bisa memanipulasi data lewat panel `/admin`.

### C. Algoritma Injeksi Data (Auto-Seeding)
Mengingat transisi dari data lawas (file lokal) ke tabel database kosong sering menjadi tantangan operasional, sistem ini dilengkapi *algoritma auto-seed* (`src/app/(frontend)/api/seed/route.ts`):
1. Menginisialisasi *Local API* milik Payload.
2. Melakukan kueri pengecekan (`totalDocs === 0`) pada tiap koleksi untuk mencegah duplikasi (injeksi ganda).
3. Melakukan *looping* terstruktur terhadap struktur data lawas (dari *legacy mock*), memetakan dan mentransformasikannya (*mapping*) agar sesuai dengan tipe skema Drizzle yang ketat.
4. Mengeksekusi penulisan *batch* (`payload.create()`) untuk mengisi sistem CMS secara otomatis dengan sekali panggil lewat HTTP GET request.

## 4. Struktur Direktori Backend

```text
src/
├── collections/               # Definisi Tabel (Schema Builder)
│   ├── Lecturers.ts           # Skema Dosen
│   ├── News.ts                # Skema Berita
│   ├── CurriculumTracks.ts    # Skema Kurikulum
│   ├── Partners.ts            # Skema Afiliasi
│   ├── Media.ts               # Skema Unggahan
│   └── Users.ts               # Skema Pengguna CMS
├── app/
│   ├── (payload)/             # Route group khusus milik Payload Admin Panel (/admin)
│   └── (frontend)/api/seed/   # Custom REST API endpoint untuk seeding
├── payload.config.ts          # Orchestrator backend (Plugin, Adapter DB, Collections)
└── payload-types.ts           # Tipe data TypeScript (Auto-generated by Payload)
```

## 5. Rencana Skalabilitas (Production Readiness)

Arsitektur MVP ini menggunakan SQLite berbasis file lokal untuk mempermudah pengembangan awal (*Local-First Development*). 
Ketika CMS portal ini memasuki tahap operasional berskala masif (Tahap Produksi Sesungguhnya):
- **Adapter Database**: SQLite (`@payloadcms/db-sqlite`) dapat ditukar (swap) dengan adapter PostgreSQL (`@payloadcms/db-postgres`) dalam `payload.config.ts` hanya dengan mengganti satu baris kode, tanpa harus mengubah *frontend* maupun logika *Collections*.
- **Media Storage**: Modul `Media.ts` saat ini menyimpan *file* fisik di server lokal (`public/media`). Kedepannya dapat disambungkan dengan *Plugin Cloud Storage* (seperti Amazon S3 atau Vercel Blob) untuk memastikan skalabilitas jika dijalankan pada infrastruktur Serverless.
